# php-7.2 phase

The first modernization phase: flat as it stood in 2020, running on PHP 7.2,
with a full test suite and its known bugs fixed. The project plan, branch
model and the rules every phase follows are in [../README.md](../README.md).

## Status (2026-11-13)

- **Tests:** 1,305 tests pass on PHP 7.2.34 with 100% class, method and line
  coverage. How to run them: [../testing.md](../testing.md).
- **Known defects (in progress):** 68 tracked, 4 fixed, 64 open.
  - 44 clear bugs: no input needed, being worked through.
  - 18 need the owner's decision, and 2 unfinished stubs need implement-or-retire
    decisions: 20 owner questions are open at the bottom of
    [active/known-defects.md](active/known-defects.md).
  - 5 test-strength tasks (TS-01 to TS-05).
- **Not started:** functional tests against `flat-webapp`.
- **Not done until** the owner declares the phase complete.

## Resume here

For a person or an agent picking this up:

1. Read the phase rules in [../README.md](../README.md) and the repository
   rules in [`AGENTS.md`](../../../AGENTS.md).
2. Run the tests (`./tests.sh`, see [../testing.md](../testing.md)) and
   confirm they pass before changing anything.
3. Pick open work from [active/known-defects.md](active/known-defects.md).
   Category A items can be fixed directly; B and C items wait for the owner's
   answer to their question. `./tests.sh unit --group known-defect` lists the
   tests that still assert defective behavior.
4. For each fix, follow "How each fix lands" in
   [active/known-defects.md](active/known-defects.md): fix the source, rewrite
   the test, remove its `@group known-defect`, add a row to
   [active/consumer-impact.md](active/consumer-impact.md), mark the entry
   fixed, and add an entry to [CHANGELOG.md](CHANGELOG.md).
5. Before touching an area, read its file in [notes/](notes/) for how it is
   tested and which quirks are deliberate.
6. Update the status section above when the numbers change.

## Next

1. Fix the open category A defects in small, separately committed batches.
2. Apply the owner's answers to the open questions (B and C items).
3. Close the test-strength tasks.
4. Write functional tests with `flat-webapp`.
5. Owner decides the phase is complete; then it moves to `modernize-26`.

## Conventions

- Lowercase-with-hyphens file names; `README.md` and `CHANGELOG.md` are the
  only uppercase names.
- The folder says what kind of document; the file name says what it is about.
- `active/` is current work, `notes/` is lasting reference, `history/` is
  finished or replaced. Nothing is deleted; superseded files move to
  `history/` with a banner.
- Every phase folder (`php-7.3/` and so on) uses the same skeleton.
